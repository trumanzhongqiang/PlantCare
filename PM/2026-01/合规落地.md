# RootMate欧美合规落地
遵循三个原则：

* **先卡死高破坏力风险（COPPA / 误导）**
* **只做“美国 P0 必要合规”，不超配**
* **每一条都能对应到工程 / 产品 / 运营责任人**



---

## Phase 0｜立项前（必须全部完成）

### 用户与市场定位

* [ ] 明确产品目标用户：**18+ 成人**
* [ ] 产品简介、App Store 文案中 **避免儿童导向语言**
* [ ] 明确不以“陪伴 / 情绪依赖”为核心卖点

---

### COPPA 高破坏力风险隔离

* [ ] 注册流程加入 **年龄确认（18+）**
* [ ] 明确写入 ToS：产品不面向 13 岁以下用户
* [ ] 禁止使用：

  * 卡通儿童风格视觉
  * “陪你”“我懂你心情”等措辞
* [ ] 产品内不设计：

  * 连续打卡奖励
  * 情绪依赖型成长叙事

---

## Phase 1｜产品与交互设计（How）

### 拟人化交互边界控制

* [ ] 拟人化人格定位为 **功能型助手**
* [ ] 所有拟人化语言满足：

  * 不暗示情感关系
  * 不暗示依赖
* [ ] 统一人格语气白名单（可复用）

---

### AI 内容安全与责任控制

* [ ] 所有养护建议加入固定免责声明模块
* [ ] 明确 AI 建议为参考，而非专业诊断
* [ ] 禁止输出：

  * 农药、化学品的具体购买或使用指导
* [ ] 病虫害类建议需满足：

  * 地域信息存在才可输出
  * 否则降级为“可能原因列表”

---

## Phase 2｜数据设计与工程实现（What）

### 数据最小化（P0）

* [ ] 明确 P0 只采集：

  * 植物 / 环境数据
  * App 基础行为数据
* [ ] 禁止采集：

  * 精准 GPS
  * 家庭成员信息
* [ ] 行为数据不做长期画像

---

### 数据分级与存储策略

* [ ] 原始数据（图像 / 语音）：

  * 仅短期缓存
  * 自动删除（如 24–72 小时）
* [ ] 长期保留数据：

  * 仅保留脱敏 / 聚合结果
* [ ] 建立数据分类表（内部文档）

---

## Phase 3｜数据流与架构（Where）

### 美国优先的数据架构

* [ ] 使用美国区域云（AWS / GCP US）
* [ ] 明确数据流：

  * 设备 → App → US 云 → 脱敏 → 结果
* [ ] 中国团队：

  * 仅访问日志 / 统计
  * 不直接访问原始用户数据

---

### 权限与审计

* [ ] 内部人员数据访问分级
* [ ] 所有访问行为有日志
* [ ] 禁止工程人员直连生产用户数据

---

## Phase 4｜法律与文档（Who + What）

### 隐私与条款文档

* [ ] 独立隐私政策页面（英文）
* [ ] 明确说明：

  * 收集哪些数据
  * 用于什么目的
  * 是否共享 / 出售（默认否）
* [ ] 明确用户权利：

  * 删除
  * 导出
  * 停止使用

---

### App Store / Play Store 合规

* [ ] 隐私标签准确填写
* [ ] 不选择 “Designed for Children”
* [ ] 所有权限说明与实际一致

---

## Phase 5｜公司与运营结构

### 公司主体与责任隔离

* [ ] 使用美国公司主体作为产品发布方
* [ ] 数据处理责任主体为美国公司
* [ ] 中国团队作为技术支持 / 开发外包角色

---

### 客服与风险响应

* [ ] 建立用户投诉处理流程
* [ ] 明确“合规问题”升级路径
* [ ] 高风险投诉（儿童 / 隐私）48 小时内响应

---

## Phase 6｜上线前检查（Go / No-Go）

* [ ] 年龄门槛完整测试
* [ ] 随机抽检拟人化文案是否越界
* [ ] 数据删除机制实测
* [ ] 隐私政策与实际行为一致

---

## Phase 7｜上线后监控（持续）

* [ ] 定期复查用户画像是否偏向未成年人
* [ ] 监控 AI 输出是否出现高风险建议
* [ ] 新功能默认 **不进入欧盟市场**
* [ ] 欧盟市场单独立项，不复用当前架构
